# 実機受入の準備: 必要な入力と確認手順(Issue #1)

Issue #1 で未完了の受入条件(実図面での検出・積算結果、SekisanNavi 実画面)を確認するために、**外部から受け取る必要があるもの**と手順。
実図面・認証情報・本番のパスは、このリポジトリにコミットしない(受け渡し方法は §6)。本番 API・共有・実 DWG・ホスト・設計サーバーには接続しない。

## 1. 検証用の図面(利用許可済みのもの)
- 画像(PNG。推論サーバーは png/jpeg/jpg を受け付ける)または PDF。**利用許可(社内の承認)を得たもの**だけ。
- 製番・ページ番号が分かること(`{page}.png` の形で検証出力ルートに置く)。
- 取り扱い範囲(持ち出し可否・保管場所・検証後の削除期限)を依頼者が明示する。

## 2. ページごとの期待値
ページ(図名・盤番号)ごとに、次を表にして受け取る。
| ページ | 期待クラス名 | 期待件数 | 位置(画像座標、px または比率)の許容誤差 |
|---|---|---|---|
- クラス名は実モデルの出力名(日本語を含む場合は UTF-8)と一致させる。0 件であるべきページも明記する。

## 3. 期待される積算 CSV・確認値
- `detected_df.csv`(CP932・BOM なし)と `estcode_df.csv` の期待値(盤ごとのコード別の数量)。
- どの設定(`app_test.yaml` の `box_types`・`initials`)・どの版の集計ロジックでの値かを併記。

## 4. SekisanNavi の検証環境とデータ配置
- Navi の起動方法・版・検証用の入力フォルダの指定方法(本番共有ではなくローカルの検証用フォルダ)。
- 配置先: 検証出力ルート(`app_test.yaml` の `data.output`、既定 `./output_test`)配下の `<storage>/output/<製番>/`。
- 確認項目: CSV が読み込めること(CP932 厳密読込)、検出枠・クラス名・積算確認画面が期待値と一致すること、スクリーンショット(個人情報・社内情報が写らない範囲)。

## 5. 本番推論サーバー管理者への確認依頼(正本・版の確定)
> **更新(前提の変更)**: 推論 API は自分たちで開発中で、稼働中の本番サーバーはまだ無い。以下は「管理者への確認」ではなく、**GPU サーバーへの配置時に版を記録して照合する項目**として扱う。暫定・隔離運用と移行条件は [inference_api_interim_operation.md](inference_api_interim_operation.md)(案)。

本番サーバーの管理者に、**読み取りだけ**で次を回答してもらう(認証情報・設定の値そのものは不要)。
1. 稼働中の `server.py` の版(ファイルの SHA256、更新日)と、参照コピー(`<参照コピー>\server.py`、sha256 `a5f454db8050d1e3…`)との一致可否。
2. 使用モデルの SHA256(参照モデル `best.pt` は `6adf124ff1eeb658…`、52,047,755 バイト)と、`model.yaml`(閾値 0.81、スライス 640・重なり 0.2、`cuda:0`)の一致可否。
3. 本番の `pip freeze`(特に `torch` / `torchvision` / `ultralytics` / `sahi` / `numpy` / `opencv-python`)。**torch が 2.5.1 か 2.6.0 かで `requirements-real.txt` の既定を決める**(`docs/inference_server.md` §9)。
4. 起動方法と、クライアント(本リポジトリ)から見た `/predict` の契約に差が無いか。

## 6. 資料の受け渡し方法
- 実図面・期待値・スクリーンショット・pip freeze は、**リポジトリにコミットせず**、社内の許可された保管場所(アクセス制限付きフォルダ)で受け渡す。ファイル名と SHA256 を依頼者とこの作業者で控える。
- ローカルでは `output_test/`(`.gitignore` 済み)に置き、検証後は期限内に削除する。
- 結果の報告(Issue #1)には、数量・OK/NG・ハッシュだけを書き、図面の内容・社内パス・認証情報は書かない。

## 7. 受け取った後の確認手順
1. `tools/verify_real_model.py --python <推論用 venv> --model-dir <モデルのフォルダ> --image <検証用画像>` で、起動→推論→出力→停止を確認(出力は `output_test\real_model_verify\`)。
2. `*_detected.txt` のクラス名・件数・位置を §2 の期待値と照合。
3. 検証設定で `app.py --config app_test.yaml`(`inference_server.backend: sahi`、ホスト照会・設計サーバー・DWG はモックまたは入力済みデータで代替)を実行し、積算 CSV を §3 と照合。
4. 出力を SekisanNavi の検証環境で読み込み、§4 の項目を確認。
5. 受入条件がすべて実証できたときだけ Issue #1 を閉じる。
