# 図面印刷の仕様(PDF)

## 1. 印刷対象と後続処理
設計製番フォルダ(`dir_design_product`)の図面(`.dwg`)のうち、**製番フォルダの `design.csv` の「ページ番号」が次の条件を満たすものだけ**を対象にする。

- 前後の空白を除いて **6 文字以内**(7 文字以上は対象外)で、空でないこと。
- 先頭が `X` / `x` でないこと(大文字小文字は区別しない)。
- 図面名(拡張子を除いたファイル名)と「ページ番号」の照合は **大文字小文字を区別しない**。**先頭ゼロは保持する**(`01` と `1` は別のページ。数値には変換しない)。
- `design.csv` に載っていない図面は対象外。

| 区分 | 対象の決め方 | PDF印刷 | 画像化・図枠検出・クロップ・推論・検出/積算データ作成 |
|---|---|---|---|
| 推論対象ページ | `.baninf` から作る `product_df` の `PAGE` のうち、上の条件を満たすもの | する | **する**(従来の工程) |
| PDFのみのページ | 上の条件を満たす、推論対象以外の図面 | する | **しない** |
| 条件外 | 上の条件を満たさない図面(7 文字以上・X/x 始まり・`design.csv` に無い) | **しない** | **しない**(推論対象・座標計算用 DF からも外す) |

- 印刷対象の並び順は従来のページ並び(文字列の昇順)、出力名は `{ページ名}.pdf`(出力先は製番フォルダ)。5枚ずつ IJCAD へ渡す点も従来どおり。
- 実装: `cad_data_process.is_printable_page_id` / `printable_page_keys` / `list_print_pages`(条件の判定と図面との照合)、`read_design_page_ids`(`design.csv` の読み取り)、`pipeline.page_plan`(印刷・推論の対象の決定)、`pipeline.product_flow`(Step.2)。
- **`design.csv` を読み取れない製番は失敗**にする(ファイルが無い・CP932 でない・見出し行が想定と違う・列数が違う行がある・データ行が無い)。条件なしで全図面を印刷してしまわないため、安全側に倒している。失敗した製番は後片付けされ、次回の実行でやり直される。
- 条件外の図面は、印刷しないだけでなく、`baninf_pages`(推論・DXF 変換・画像化の対象)と `product_df`(座標計算)にも入れない。どのページを条件外としたかは、処理ログ(`excluded_pages`)に残す。
- 推論対象ページが設計フォルダに無い製番は、印刷に進まず失敗として記録する(従来は `sys.exit()`)。推論対象ページが 0 件の製番(印刷対象が 0 件を含む)は、例外なく「スキップ」として記録して次の製番へ進む。
- 図面使用中の確認(`is_file_in_use`)は、印刷する全ページに対して行う。
- 共通製作仕様書(`1.dwg`、整理番号側のフォルダ)の印刷は、印刷位置・設定は従来どおり。ただし**専用のスクリプト(`SPEC_SHEET.SCR`)から、PDF を最初から「共通製作仕様書.pdf」へ出力する**(以前は `WIRING.SCR` で一度ページ「1」の仮名 `1.pdf` へ出し、あとで改名していた)。仮名を経由しないので、仕様書の IJCAD が見守りの上限(35 秒)を過ぎて PDF を後から出しても、後続のページ「1」の `1.pdf` と同じ名前を取り合って上書きし合わない(InterimOps の実行で、仕様書が作られなかった製番があった)。最終ファイル名・待ち時間・失敗条件は変えていない。

## 2. 印刷スクリプトと印刷位置
`WIRING.SCR` は `print_support.output_print_script` が作成する(社内共通パッケージ `bs_pkg` の同名関数と同じ手順。`bs_pkg` は Git 管理外のため、印刷設定をこのリポジトリで追跡できるようにした)。`-PLOT` の入力順:

`-PLOT` → `Y`(詳細設定)→ `Model` → `DWG To PDF` → `ISO A3 (420.00 x 297.00 MM)` → `M` → `L`(横)→ `N`(上下反転なし)→ `L`(印刷範囲: Limits)→ `F`(尺度: Fit)→ **印刷オフセット** → `Y` → `thickness.ctb` → `Y` → `A` → 出力PDFパス → `N` → `Y` → `close y`(ファイル末尾に `quit y`)

- **変更点**: 印刷オフセットを固定値 `5,5`(用紙の左下から 5mm)から `C`(用紙の中央に配置)へ変更。固定値だと、図面(Limits)と用紙の縦横比の差がすべて右または上の余白になり偏る。`C` は図面ごとの範囲から自動で左右・上下の余白を等しくするため、特定図面向けの固定オフセットを使わない。
- **変えていないもの**: 用紙(ISO A3)、印刷範囲(Limits)、尺度(Fit)。オフセットは位置だけを動かし、尺度は変えないため、PDF 上の図枠の大きさは変わらない。推論対象ページの縮尺計算は「DXF の図枠寸法 ÷ 画像から検出した図枠寸法」で、図枠検出・クロップが画像内の図枠位置を検出して行うため、位置が変わっても成立する想定(実図面での確認は未了)。
- `close y`(図面を保存せず閉じる)は維持。`close n` や引数なしの `close` にしない(テストで確認)。

### 3.2 ローカル IJCAD 2024 STD での実測(合成DWGのみ・`tools/verify_print_centering.py --no-style`)
条件: 合成DWG(ezdxf で作成し ODA File Converter で DWG 化。本番図面・共有は不使用)、用紙 ISO A3(420x297mm)、印刷範囲 Limits、尺度 Fit、オフセットだけを `5,5` と `C` で比較。Limits は印刷スクリプト内の `LIMITS` で図枠に合わせた(ODA は DXF ヘッダの Limits を DWG に残さないため)。`thickness.ctb` はこの環境で確認できず、印刷スタイルのテーブル名は `.`(なし)で実施。`close y` のまま、合成DWGの SHA256 は印刷前後で変化なし。再実行しても同じ値になった(2回)。

| 合成図面 | モード | 左余白 mm | 右余白 mm | 上 mm | 下 mm | 尺度 mm/図面単位 |
|---|---|---|---|---|---|---|
| A3横に近い(原点) | `5,5` | 10.5 | **39.9** | 17.9 | 22.6 | 0.08799 |
| 同上 | `C` | 25.0 | 25.5 | 18.0 | 17.7 | 0.08796 |
| 細長い横(遠い位置) | `5,5` | 10.5 | 6.0 | **79.9** | 22.6 | 0.09607 |
| 同上 | `C` | 5.6 | 6.1 | 51.4 | 51.1 | 0.09722 |
| 縦長(負の座標) | `5,5` | 10.5 | **285.0** | 17.9 | 22.6 | 0.06223 |
| 同上 | `C` | 147.6 | 148.0 | 18.0 | 17.7 | 0.06223 |
| 小さい図枠 | `5,5` | 10.5 | **200.4** | 17.9 | 22.6 | 0.17420 |
| 同上 | `C` | 105.3 | 105.7 | 18.0 | 17.7 | 0.17420 |

- **右余白の偏りの再現**: `5,5` では図面が用紙の左寄せになり、右余白が大きくなる。`C` では 4 種すべてで左右差 0.5mm 以内、上下差 0.4mm 以内(細長い横は縦方向の差も解消)。位置・縦横比・座標の異なる図面で機能した。
- **用紙・尺度**: 用紙は常に 420x297mm。尺度は、高さで決まる図面では `5,5` と `C` で同一。幅で決まる図面(細長い横)では `C` の方が約 1.2% 大きい(Fit が 5mm のオフセット分の余白を差し引くため)。
- **`5,5` での欠け**: A3 縦横比の図枠(1 番目)では、`5,5` だと図枠の下辺が約 5mm 用紙の印刷可能範囲から外れて欠ける(描画高さ 256.4mm、`C` は 261.2mm で全体が入る)。
- **枠検出・クロップ(既存の `specified_frame_detection`)**: A3 に近い合成図面 2 種で、`C` の PDF は図枠を検出でき(2174x1543px / 2413x1137px)、縮尺(DXF 幅 ÷ 画像の図枠幅)は 1.9319 / 1.7406。PDF 上の尺度から計算した値(約 1.92 / 1.74)と一致する。`5,5` の PDF はこの 2 種とも検出に失敗した(図枠の欠けが原因と推測。未特定)。小さい・縦長の合成図面は、検出が「画像の半分以上の長さの線」を前提とするため、`5,5`/`C` どちらも検出できない(合成図面の限界で、`C` の影響ではない)。
- **限界(重要)**: `C` は **印刷範囲(Limits)** を用紙の中央に置く。図枠が Limits の中で偏っている場合(合成の 5 番目: 図枠 3000x2000 が Limits 6000x3000 の中で偏る)は、`C` でも左 59.9 / 右 155.7mm と偏りが残る。実図面の Limits が図枠に一致しているかが効果の前提で、**未確認**。一致しない図面が多い場合は、Limits ではなく図枠(窓)を指定する方式の検討が必要(尺度・図枠検出への影響が大きいため、今回は変更していない)。

### 3.3 IJCAD の起動について(原因の整理)
- 当初の検証で `gcad /b` が終了しなかった原因は IJCAD の不具合ではなく、検証スクリプトの誤り: ①`-PLOT` の前の `layer ...` 行を省いたまま空行を入れ、空行が直前の `open` を再実行して以降の入力がずれた、②IJCAD は「印刷スタイルを使用」に `N` と答えても「印刷スタイル テーブル名」を尋ねる(`.` で「なし」)。この 2 点を本番と同じスクリプト(`print_support.build_script_lines`)に揃えて解消した。最小スクリプト(開いて `close y`・`quit y` のみ)は約 18〜27 秒で終了コード 0。
- 初回の最小スクリプトが 60 秒で終わらなかった件は、原因を特定できていない(同じ手順を後で再現すると 27 秒で終了。先に強制終了した IJCAD の残骸の影響の可能性)。
- 起動した IJCAD のプロセスだけを PID 指定で終了させ、他のプロセスには触れていない。終了後に gcad は残っていない。
- IJCAD の `-PLOT` は `C` を受け付ける(プロンプト: 「印刷オフセット(x,y)を入力 または [中心(C)] <0,0>」)ことを画面で確認した。
